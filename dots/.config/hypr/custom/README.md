# `custom/`

Your personal Hyprland overrides. Files here are loaded *after* the defaults in
`../hyprland/`, so anything you set wins.

| File | Sourced from | Purpose |
|---|---|---|
| `env.lua` | `hyprland.lua` | environment variables, read before everything else |
| `execs.lua` | `hyprland.lua` | startup commands, run in addition to the defaults |
| `general.lua` | `hyprland.lua` | general settings, e.g. `input` |
| `rules.lua` | `hyprland.lua` | window rules, appended to the defaults |
| `keybinds.lua` | `hyprland.lua` | keybinds; unbind a default before rebinding it |
| `variables.lua` | `hyprland/keybinds.lua` | values used by the default keybinds |

Every file is optional. Each is wrapped in an `is_file_exists` check before it
is required, so deleting one is safe and so is leaving it empty.

## The copies in this repo are empty templates

The versions committed here contain only comments. They exist so a fresh clone
has the files in place with the syntax documented, not so they configure
anything.

Your own `custom/` is **never** overwritten by the installer. In
`sdata/subcmd-install/3.files-exp.yaml` the entry for this directory uses
`mode: skip-if-exists`, which copies only when the destination is absent:

```bash
"skip-if-exists")
  if [[ -e "$to" ]]; then
    echo "Skipping $from (destination exists)"
  else
    v cp -r "$from" "$to"
  fi
  ;;
```

So the templates land exactly once, on first install, and every later run skips
them. Back these files up before wiping `~/.config/hypr/` — a fresh install
starts you from the templates again.
