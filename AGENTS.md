# AGENTS.md

Working rules for this repo. Read this before making changes.

## `dots/.config/hypr/custom/` is template-only, always

The files in `custom/` exist so a fresh clone has the right files in place with
the syntax documented. They must contain **comments only** — no active config.

Before every commit and every push, check that:

- the only uncommented, non-blank line in `custom/*.lua` is the "Edit user
  keybinds" self-service helper in `keybinds.lua`. That one is deliberate —
  without it a fresh install has no way to reach the file. Anything else
  uncommented is a mistake.
- no absolute paths containing a username (`/home/<something>/`) are present
- no API keys, tokens or passwords appear anywhere in the diff
- `custom/scripts/__restore_video_wallpaper.sh` is untouched — it is generated
  by `switchwall.sh` and the script overwrites it

The check is mechanical:

```bash
cat dots/.config/hypr/custom/*.lua | grep -vE '^\s*--|^\s*$'
```

Exactly one line should come back. `custom/general.lua` and
`custom/keybinds.lua` are the two that drifted in the past; the other four were
already empty.

## Never sync `custom/` from the repo to the live config

`custom/` in the repo is a template. The live `~/.config/hypr/custom/` is the
user's own and is the source of truth. **Never** copy repo → live for this
directory, and never "fix drift" by overwriting it.

The installer handles this correctly on its own — the entry in
`sdata/subcmd-install/3.files-exp.yaml` is `mode: skip-if-exists`, so the
templates are copied only when `~/.config/hypr/custom/` is absent and are
skipped on every later run. No installer change is needed, and changing that
mode to `sync` or `soft` would destroy the user's config on the next run.

Because of this, `diff -r` between the live and repo copies of `custom/` is
**expected to differ** and that is not drift to fix.

## Same rule for the other locally-owned files

These are also expected to differ between live and repo. Do not sync them.

| Path | Why |
|---|---|
| `~/.config/hypr/hyprland/colors.lua` | generated by matugen |
| `~/.config/hypr/hyprlock/colors.conf` | generated by matugen |
| `~/.config/hypr/hyprland/shellOverrides/main.lua` | local `hl.config` overrides |
| `~/.config/akari/config.json` | holds API keys; outside the repo entirely |

`colors.lua` and `colors.conf` are additionally synced with `mode: soft-backup`
in the installer, so they update on purpose. `shellOverrides/main.lua` is not
synced at all.

## Bluetooth and other machine config is not repo work

`/etc/bluetooth/main.conf` and anything else under `/etc` is machine state.
Change it on the machine, verify it, and do not commit it. Bluetooth is set to
`AutoEnable=false`; `rfkill unblock bluetooth` has to be re-run after a reboot
if the `ideapad` driver re-asserts the soft block, otherwise the bar's
Bluetooth toggle silently fails.

## Before committing or pushing

Ask first, and show the verification results before the user says go. Nothing
gets pushed without an explicit yes.

- `qmllint` from `/usr/lib/qt6/bin` on every changed `.qml`. Note
  `/usr/bin/qmllint` and `/usr/lib/qt6/bin/qml` are Qt5 builds and silently do
  nothing useful. Runtime testing is `QT_QPA_PLATFORM=offscreen qs -p <file>`.
- `bash -n` on changed shell scripts, `luac -p` on changed `.lua`.
- Deploy to the live config, confirm the watcher reloaded, and confirm the
  change in the log at `/run/user/<uid>/quickshell/by-id/*/log.qslog`. The
  instance id changes when the shell restarts — re-check the path, do not
  assume the old one. Errors before the reload marker in the log are stale.
- Scan the diff for key-shaped strings before pushing.
- Keep the `end-4` / `pctrade` GPL-3.0 attribution and `LICENSE` intact.
